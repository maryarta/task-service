## Сервис очереди задач на обработку файлов

#### Сервис поддерживает:
* создание задачи на обработку файла
* получение задачи по id
* получение списка задач
* постановку задачи в очередь
* отмену задачи
* фильтрацию задач по статусу, типу и времени создания
* пагинацию
* асинхронную фоновую обработку задач
* ограничение количества одновременно выполняемых задач через конфигурацию
* сохранение результата обработки
* сохранение ошибки обработки
* восстановление зависших задач

#### Статусы задач
Жизненный цикл задачи включает следующие переходы статусов:

`CREATED` → `QUEUED` → `PROCESSING` → `DONE`  
`CREATED` → `QUEUED` → `PROCESSING` → `FAILED`  
`CREATED` → `QUEUED` → `CANCELED`  
`CREATED` → `CANCELED`

Для зависших задач предусмотрено восстановление:

`PROCESSING` → `QUEUED`

Описание статусов
| Статус      | Описание                                           |
|-------------|----------------------------------------------------|
| CREATED     | задача создана, но еще не поставлена в очередь     |
| QUEUED      | задача находится в очереди и ожидает обработки     |
| PROCESSING  | задача обрабатывается                              |
| DONE        | задача успешно обработана                          |
| FAILED      | при обработке произошла ошибка                     |
| CANCELED    | задача отменена пользователем                      |

#### Типы задач
Поддерживаются следующие типы задач
| Тип         | Описание                                           |
|-------------|----------------------------------------------------|
| CONVERT     | имитация конвертации файла                         |
| ARCHIVE     | имитация архивации файла                           |
| VALIDATE    | проверка имени файла на наличие расширения         |

#### Очередь задач
Очередь реализована через базу данных: задачами в очереди считаются записи со статусом `QUEUED`.
Пользователь может поставить созданную задачу в очередь.
Фоновые процессы периодически проверяют базу данных, выбирают следующую задачу из очереди, переводят ее в статус `PROCESSING` и обрабатывают.

#### Восстановление зависших задач
Если задача находится в статусе `PROCESSING` дольше заданного времени, она считается зависшей.
Периодическая проверка зависших задач возвращает их обратно в очередь.  
Например, если приложение остановится во время обработки, задача может остаться в статусе `PROCESSING`.
После перезапуска она будет переведена обратно в `QUEUED` и сможет быть обработана повторно.

#### Конфигурация
Основные параметры задаются в application.properties.  
| Параметр                                     | Описание                                                             |
|----------------------------------------------|----------------------------------------------------------------------|
| task.processing.max-concurrent-tasks         | максимальное количество одновременно обрататывающихся задач          |
| task.processing.polling-delay-ms             | задержка между проверками очереди, если задач нет                    |
| task.recovery.processing-timeout-seconds     | время, после которого задача в PROCESSING считается зависшей         |
| task.recovery.fixed-delay-ms                 | периодичность проверки зависших задач                                |
